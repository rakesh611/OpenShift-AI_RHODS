Data Science Pipelines in OpenShift AI

In Red Hat OpenShift AI, Data Science Pipelines (DSP) are used to automate, orchestrate, version, and operationalize end-to-end ML workflows such as:

Data ingestion

Data preprocessing

Feature engineering

Model training

Validation/testing

Model packaging

Deployment

Monitoring

Retraining

Technically, OpenShift AI Data Science Pipelines are based on:

Kubeflow Pipelines

Kubernetes-native workflow execution

Containerized pipeline components

Tekton/Kubernetes concepts

Argo workflow concepts internally (depending on version)

Official references:

Red Hat OpenShift AI Documentation

Kubeflow Pipelines Documentation

3. Core Components of Data Science Pipelines

A. Pipeline SDK

Data scientists define workflows using Python.

Example:
```python
@dsl.pipeline(
    name="fraud-detection-pipeline"
)
def pipeline():
    preprocess_task = preprocess_op()
    train_task = train_op()
    train_task.after(preprocess_task)
```
SDK converts workflow into executable pipeline.

B. Pipeline Server

Responsible for:

Pipeline execution

Scheduling

Tracking runs

Managing metadata

DAG orchestration

Runs inside OpenShift cluster.

15. Example Pipeline Code

Simple Kubeflow Pipeline
```python
from kfp import dsl

@dsl.component
def preprocess():
    print("Preprocessing")

@dsl.component
def train():
    print("Training")

@dsl.pipeline(name="ml-pipeline")
def pipeline():
    p = preprocess()
    t = train()
    t.after(p)
```

21. Best Practices

Use Immutable Containers

Avoid installing packages during runtime.

Externalize Configurations

Use:

ConfigMaps

Secrets

Use GitOps

Store pipeline definitions in Git.

Enable Monitoring

Track:

Pipeline duration

GPU utilization

Failure rate

Use Resource Limits

Prevent noisy-neighbor issues.

Example:
```yaml
resources:
  requests:
    memory: "4Gi"
```
