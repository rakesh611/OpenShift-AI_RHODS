Core Components of OpenShift AI

1. Dashboard / Web Console

The central UI for:

Data scientists

ML engineers

Platform admins

Functions:

Launch notebooks

Manage models

Configure pipelines

Deploy models

Monitor resources

Access GPUs

Senior-level explanation:

Dashboard acts as the control plane UI for AI lifecycle management inside OpenShift.

2. Workbenches (Notebook Environments)

This is one of the most important components.

Provides:

Jupyter Notebook

JupyterLab

VS Code IDE

TensorFlow/PyTorch runtime images

Features:

Runs as Kubernetes pods

Persistent storage

GPU attachment

Custom container images

Secure multi-user isolation

Example:

```plain
Data Scientist -> Launches JupyterLab
                -> Gets dedicated pod
                -> Pod attached to PVC + GPU
```
Interview Point:

Each workbench is essentially a containerized development environment running on OpenShift.

Connections

7. Model Serving

Very important enterprise component.

OpenShift AI supports:

A. Single Model Serving

One model per pod.

Good for:

Dedicated inference

KServe

B. Multi-Model Serving

Multiple models shared on same infrastructure.

Uses:

ModelMesh

Benefits:

Better GPU utilization

Lower memory usage

Dynamic loading/unloading

Enterprise use case:

```plain

served from shared cluster
```

OpenShift AI is an enterprise MLOps platform built on OpenShift that provides notebook environments, GPU orchestration, model training, pipelines, model registry, model serving, monitoring, and multi-tenant AI lifecycle management using Kubernetes-native components like KServe, Kubeflow Pipelines, Operators, and Service Mesh. It enables organizations to operationalize AI workloads securely and at scale.
