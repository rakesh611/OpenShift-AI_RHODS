# 17. Reproducible images

## Purpose

This guide explains Reproducible images from architecture through production operations.

The project deliverable is a working **reproducible image build**.

The example image is `quay.example.com/rhoai/reproducible-ai:1.0.0`.

The starting point is **digest-pinned base image**.

The expected command is `image-specific` and the primary port is `8080`.

The audience is a senior OpenShift, Linux, Kubernetes, DevOps, MLOps, security, or SRE engineer.

## Support and version boundary

Red Hat supports adding custom workbench images to OpenShift AI, but the custom image contents remain the customer's responsibility.

Custom serving runtimes also require customer ownership for licensing, configuration, testing, and maintenance.

Dashboard paths and custom resource fields can change between releases.

Validate every manifest against the APIs installed in the target cluster.

## Learning outcomes

- Design the image as a maintained platform product.
- Build it locally and inside OpenShift.
- Run under restricted OpenShift security.
- Pin base and language dependencies.
- Publish to internal and external registries.
- Integrate through ImageStreams and OpenShift AI resources.
- Generate SBOMs, scan, sign, attest, and promote.
- Validate performance, storage, networking, probes, and accelerator behavior.
- Troubleshoot every major failure layer.
- Operate updates, rollback, deprecation, and retirement.

## Reference architecture
1. Git stores Containerfile, locks, code, tests, manifests, and policies.
2. CI resolves immutable inputs, tests, builds, creates SBOM, scans, and signs.
3. The OCI registry stores layers, manifests, signatures, attestations, and retention data.
4. ImageStreams provide an OpenShift abstraction and controlled tags.
5. OpenShift AI consumes the image through workbench or serving resources.
6. GitOps promotes the same immutable digest across environments.
7. Runtime policy enforces non-root, seccomp, dropped capabilities, resources, and network restrictions.
8. Monitoring records startup, readiness, requests, errors, latency, memory, CPU, storage, and GPU signals.
9. Operations owns patches, rollback, deprecation, retention, and retirement.

### Step 3: Containerfile
```Dockerfile
ARG BASE_IMAGE=registry.access.redhat.com/ubi9/python-311@sha256:REPLACE_WITH_APPROVED_DIGEST
FROM ${BASE_IMAGE}
USER 0
RUN dnf install -y --setopt=tsflags=nodocs ca-certificates curl-minimal && dnf clean all && rm -rf /var/cache/dnf
RUN mkdir -p /opt/app-root/src /models /tmp/runtime && chgrp -R 0 /opt/app-root /models /tmp/runtime && chmod -R g=u /opt/app-root /models /tmp/runtime
USER 1001
COPY --chown=1001:0 requirements.lock /tmp/requirements.lock
RUN python -m pip install --no-cache-dir --require-hashes -r /tmp/requirements.lock && python -m pip check
COPY --chown=1001:0 app/ /opt/app-root/src/app/
WORKDIR /opt/app-root/src
ENV PYTHONUNBUFFERED=1 MODEL_DIR=/models PORT=8080
EXPOSE 8080
USER 1001
CMD ["sh","-c","image-specific"]
```

The image uses root only for build-time package installation.
The final runtime user is non-root.
Writable directories use group 0 and group-equal-user permissions for OpenShift random UID compatibility.
The final image excludes credentials, package caches, compilers, and user data.

### Step 5: Build and test locally
```bash
export IMAGE=quay.example.com/rhoai/reproducible-ai:1.0.0
podman build --no-cache -t "$IMAGE" .
podman run --rm --user 1000710000:0 "$IMAGE" id
podman run --rm --user 1000710000:0 "$IMAGE" sh -c 'touch /tmp/uid-test && python -m pip check'
podman inspect "$IMAGE" > evidence/image-inspect.json
podman history --no-trunc "$IMAGE" > evidence/image-history.txt
```

### Step 6: SBOM, scan, push, and sign
```bash
syft "$IMAGE" -o cyclonedx-json > evidence/sbom/sbom.cdx.json
grype "$IMAGE" -o json > evidence/scans/scan.json
podman push "$IMAGE"
DIGEST=$(skopeo inspect docker://"$IMAGE" | jq -r .Digest)
echo "$IMAGE@$DIGEST" | tee evidence/approved-image.txt
cosign sign "$IMAGE@$DIGEST"
cosign verify "$IMAGE@$DIGEST"
```

### Step 7: Pull secret and service account
```bash
oc new-project rhoai-images || true
oc -n rhoai-images create secret docker-registry registry-pull \
  --docker-server=quay.example.com \
  --docker-username="$REGISTRY_USER" \
  --docker-password="$REGISTRY_PASSWORD"
oc -n rhoai-images create serviceaccount reproducible-images-runtime || true
oc -n rhoai-images secrets link reproducible-images-runtime registry-pull --for=pull
```

Never commit registry credentials.
Use the exact service account used by the workload.
Rotate credentials without rebuilding the image.
### Step 8: ImageStream
```yaml
apiVersion: image.openshift.io/v1
kind: ImageStream
metadata:
  name: reproducible-images
  namespace: rhoai-images
  labels:
    opendatahub.io/dashboard: "true"
  annotations:
    opendatahub.io/notebook-image-name: "Reproducible images"
spec:
  lookupPolicy:
    local: true
  tags:
  - name: stable
    from:
      kind: DockerImage
      name: quay.example.com/rhoai/reproducible-ai@sha256:REPLACE_WITH_APPROVED_DIGEST
    importPolicy:
      scheduled: false
    referencePolicy:
      type: Local
```

An ImageStream stores metadata and references, not the actual image layers.
Inspect status.tags to prove a successful import.
Use scheduled imports only when automatic change is intended and tested.
### Step 9: Restricted validation deployment
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: reproducible-images
  namespace: rhoai-images
spec:
  replicas: 1
  selector:
    matchLabels:
      app: reproducible-images
  template:
    metadata:
      labels:
        app: reproducible-images
    spec:
      serviceAccountName: reproducible-images-runtime
      securityContext:
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: runtime
        image: quay.example.com/rhoai/reproducible-ai@sha256:REPLACE_WITH_APPROVED_DIGEST
        ports:
        - name: http
          containerPort: 8080
        securityContext:
          allowPrivilegeEscalation: false
          capabilities:
            drop: ["ALL"]
          runAsNonRoot: true
          readOnlyRootFilesystem: true
        resources:
          requests:
            cpu: 250m
            memory: 512Mi
          limits:
            cpu: "2"
            memory: 4Gi
        readinessProbe:
          httpGet:
            path: /health/ready
            port: http
        livenessProbe:
          httpGet:
            path: /health/live
            port: http
        volumeMounts:
        - name: tmp
          mountPath: /tmp
      volumes:
      - name: tmp
        emptyDir: {}
```

### Step 11: GitOps promotion
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1

```

Development, test, and production must use the same immutable digest.
Do not rebuild separately for production.

## Senior troubleshooting methodology
Start with immutable image identity, then inspect registry, ImageStream, pull secret, service account, pod scheduling, SCC, runtime, probes, route, storage, network, GPU, and application.
```bash
oc get pod -o wide
oc describe pod <pod>
oc get events --sort-by=.lastTimestamp
oc logs <pod> --all-containers=true --previous
oc get pod <pod> -o yaml
oc get imagestream -o yaml
oc get secret,serviceaccount
oc auth can-i --list
```
