What is NVIDIA GPU Operator?

The NVIDIA GPU Operator is a Kubernetes Operator that automates:

GPU driver installation

NVIDIA Container Toolkit setup

Device plugin deployment

GPU monitoring

MIG management

GPU scheduling integration

CUDA runtime enablement

DCGM telemetry

Node labeling and validation

It converts GPU infrastructure management into a Kubernetes-native lifecycle.

Instead of manually installing drivers and configuring runtime on every GPU node, the Operator handles the complete GPU software stack automatically.

Official Platform: NVIDIA GPU Operator Documentation

3. NVIDIA Driver Container

Purpose

Installs GPU kernel drivers dynamically on GPU nodes.

Without this:

GPU hardware invisible to OS

CUDA impossible

Traditional Method

Normally:
```bash
yum install nvidia-driver
reboot
```
Operator method:

Driver runs inside privileged container

Compiles kernel module

Injects into host kernel

No manual install

Driver DaemonSet
```bash
nvidia-driver-daemonset
```
Runs only on GPU nodes.

Important Internals

The driver container:

mounts /usr/src

mounts kernel headers

builds kernel modules

loads:

nvidia

nvidia_uvm

nvidia_modeset

Check:
```bash
lsmod | grep nvidia
```

8. MIG Manager (Multi-Instance GPU)

Critical for enterprise AI clusters.

What is MIG?

Supported on:

A100

H100

newer Hopper GPUs

MIG partitions one physical GPU into multiple logical GPUs.

Example:
```plain
1 A100 80GB
   ↓
7 isolated GPU instances
```
Why MIG Matters

Instead of:
```plain
1 GPU = 1 workload
```
you get:
```plain
1 GPU = many workloads
```
Massively improves utilization.

MIG Profiles

Examples:
```plain
1g.10gb
2g.20gb
3g.40gb
```
Operator MIG Automation

GPU Operator can:

enable MIG mode

Difference Between Device Plugin and GPU Operator?

| Component     | Purpose                  |
| ------------- | ------------------------ |
| Device Plugin | Advertises GPU resources |

Difference Between MIG and Time-Slicing?

| MIG                      | Time-Slicing       |
| ------------------------ | ------------------ |
| Hardware isolation       | Software sharing   |
| Dedicated memory         | Shared memory      |
| Strong isolation         | Weak isolation     |
| Production multi-tenancy | Dev/Test workloads |
