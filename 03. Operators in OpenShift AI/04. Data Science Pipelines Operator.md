The Data Science Pipelines Operator (DSPO) in OpenShift AI is the component responsible for deploying, managing, upgrading, and operating the Kubeflow Pipelines (KFP) ecosystem on top of OpenShift.

Think of it as:

“The Kubernetes-native control plane that operationalizes ML workflow orchestration inside OpenShift AI.”

It automates:

Pipeline engine deployment

Workflow CRD management

Multi-tenant pipeline isolation

Artifact storage integration

Pipeline scheduling/execution

ML workflow lifecycle management

Upgrade and reconciliation logic

1. Why Data Science Pipelines Exist

In enterprise AI/ML environments, data scientists do not just train models once.

They need repeatable workflows:
```plain
Data Ingestion
   ↓
Data Validation
   ↓
Feature Engineering
   ↓
Model Training
   ↓
Evaluation
   ↓
Approval
   ↓
Model Registry
   ↓
Deployment
```
Running these manually is impossible at scale.

So organizations require:

Reproducibility

Automation

Scheduling

Experiment tracking

Versioning

Auditability

CI/CD integration

GPU orchestration

Failure recovery

This is where:

Kubeflow Pipelines

Argo Workflows

Tekton

ML orchestration frameworks

become critical.

The Data Science Pipelines Operator manages this stack.

6. Kubernetes CRDs Used

DSPO heavily relies on Custom Resource Definitions.

Important CRDs

| CRD                             | Purpose                    |
| ------------------------------- | -------------------------- |
| DataSciencePipelinesApplication | Main pipeline deployment   |
| Workflow                        | Argo workflow              |
| ScheduledWorkflow               | Scheduled pipelines        |
| Experiment                      | Experiment grouping        |
| Run                             | Pipeline execution         |
| Pipeline                        | Stored pipeline definition |

kind: DataSciencePipelinesApplication

  name: ds-pipeline

    deploy: true

    deploy: true
